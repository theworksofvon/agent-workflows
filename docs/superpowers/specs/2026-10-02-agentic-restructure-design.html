agent-workflows: the redesign

Code does the deterministic steps. The agent makes the judgment calls. GitHub pushes events in, instead of us polling for them.

GitHub Code (deterministic) Agent (judgment)
Comment landsSomeone leaves 12 review comments on a PR.
Webhook receives itGitHub POSTs to the daemon. Signature checked, delivery ID deduped.
Batch gateWait 10s of quiet. Group by PR and review. One run, not twelve.
DispatchOne lane per PR, at most 3 running at once.
Worktree + packetClone, check out the branch, pin the base SHA, write packet.json.
Agent runsFull harness session. Reads packet, uses the pr-feedback skill, does whatever it judges right.
Agent writes reportPer comment: addressed, skipped, or needs_human, with a reason. Mandatory.
Validate + pushEvery key accounted for? Commit leftovers. Push with lease on the pinned SHA.
Reply + summarizeReply on each skipped thread with the reason. One marker summary comment.
DoneMark all 12 processed. Lane frees. Nobody was paged.

Code decides

  • Which comments form a batch and when it is ready
  • Who is allowed to trigger a run (author allowlist, bot filter)
  • Worktree, branch, base SHA
  • Whether anything was committed and whether to push
  • What gets posted to GitHub and in what shape
  • Retries, dedupe, marking processed

Agent decides

  • Which of the comments to act on, skip, or escalate, and why
  • What a comment actually means and what change it implies
  • What to inspect, what to edit, what tests to run
  • How many commits and what goes in them
  • The wording of every reply and the summary
  • Whether a comment is answerable at all
Concrete example. 12 comments arrive. Code batches them and launches the agent. The agent fixes 7, notices 3 ask for something already done in an earlier commit, and judges 2 as conflicting with the PR's stated design. It writes a report saying exactly that. Code pushes the 7 fixes, replies on the 3 with "already handled in abc123", replies on the 2 with the agent's reasoning, posts one summary, and moves on. The 2 flagged threads are labels, not blockers. If the author replies, that's just a new comment.

The seam is a file. Code writes packet.json in. The agent writes report.json out. Nothing in the launch prompt tells the agent how to do its job; the pr-feedback skill in vstack carries the judgment rules.

A webhook means something is always listening. The daemon is one process that binds a host and port. How the outside world reaches it is a separate, pluggable layer, the same way t3code treats Tailscale as an add-on and not a core concept. Pick where you'd run it:

This MacTailscale is already installed. Funnel exposes one port with a real HTTPS cert.
HomelabYou already have ingress, or run Funnel there too. Install as a systemd service.
Someone else's boxAny VPS or tunnel. They provide the public URL, the daemon registers it.
